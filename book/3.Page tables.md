### Page tables（页表）

---

**Page tables are the most popular mechanism through which the operating system provides each process with its own private address space and memory. Page tables determine what memory addresses mean, and what parts of physical memory can be accessed. They allow xv6 to isolate different process’s address spaces and to multiplex them onto a single physical memory. Page tables are a popular design because they provide a level of indirection that allow operating systems to perform many tricks. Xv6 performs a few tricks: mapping the same memory (a trampoline page) in several address spaces, and guarding kernel and user stacks with an unmapped page. The rest of this chapter explains the page tables that the RISC-V hardware provides and how xv6 uses them.**

页表是操作系统为每个进程提供私有地址空间和内存的最常见机制。页表决定了内存地址的含义，以及哪些物理内存区域可以被访问。它们使 xv6 能够隔离不同进程的地址空间，并将它们复用到同一块物理内存上。页表之所以常见，是因为它们提供了一层间接性，使操作系统能够做很多“技巧”。xv6 也做了一些技巧：在多个地址空间中映射相同的内存（跳板页 trampoline page），以及通过未映射页来保护内核和用户栈。本章其余部分将解释 RISC-V 硬件提供的页表，以及 xv6 是如何使用它们的。

---

### 3.1 Paging hardware

**As a reminder, RISC-V instructions (both user and kernel) manipulate virtual addresses. The machine’s RAM, or physical memory, is indexed with physical addresses. The RISC-V page table hardware connects these two kinds of addresses, by mapping each virtual address to a physical address.**

提醒一下，RISC-V 的指令（用户态和内核态）操作的都是虚拟地址。机器的 RAM（物理内存）通过物理地址进行索引。RISC-V 的页表硬件连接了这两种地址，通过将虚拟地址映射为物理地址来完成转换。

---

**Xv6 runs on Sv39 RISC-V, which means that only the bottom 39 bits of a 64-bit virtual address are used; the top 25 bits are not used. In this Sv39 configuration, a RISC-V page table is logically an array of 2^27 (134,217,728) page table entries (PTEs). Each PTE contains a 44-bit physical page number (PPN) and some flags.**

xv6 运行在 **Sv39 RISC-V** 上，这意味着 64 位虚拟地址中只有低 39 位被使用，高 25 位不被使用。在 Sv39 模式下，RISC-V 页表在逻辑上是一个包含 2²⁷（134,217,728）个页表项（PTEs）的数组。每个 PTE 包含一个 **44 位物理页号（PPN）** 以及一些标志位。

---

**The paging hardware translates a virtual address by using the top 27 bits of the 39 bits to index into the page table to find a PTE, and making a 56-bit physical address whose top 44 bits come from the PPN in the PTE and whose bottom 12 bits are copied from the original virtual address. Figure 3.1 shows this process with a logical view of the page table as a simple array of PTEs (see Figure 3.2 for a fuller story). A page table gives the operating system control over virtual-to-physical address translations at the granularity of aligned chunks of 4096 (2^12) bytes. Such a chunk is called a page.**

分页硬件通过以下方式翻译虚拟地址：使用虚拟地址的高 27 位在页表中索引，找到一个 PTE；物理地址的高 44 位来自该 PTE 的 PPN，而低 12 位直接拷贝自原虚拟地址。图 3.1 用页表作为简单数组的逻辑视图展示了这个过程（图 3.2 提供了更完整的说明）。页表让操作系统能够以 **4096 字节（2¹²）对齐的块** 为粒度控制虚拟地址到物理地址的映射。这种块称为 **页（page）**。

---

**In Sv39 RISC-V, the top 25 bits of a virtual address are not used for translation. The physical address also has room for growth: there is room in the PTE format for the physical page number to grow by another 10 bits. The designers of RISC-V chose these numbers based on technology predictions. 2^39 bytes is 512 GB, which should be enough address space for applications running on RISC-V computers. 2^56 is enough physical memory space for the near future to fit many I/O devices and RAM chips. If more is needed, the RISC-V designers have defined Sv48 with 48-bit virtual addresses \[3].**

在 Sv39 RISC-V 中，虚拟地址的高 25 位不参与转换。物理地址格式也预留了扩展空间：PTE 格式中为物理页号额外预留了 10 位。RISC-V 的设计者基于技术预测选择了这些数值。2³⁹ 字节（512 GB）足以作为 RISC-V 应用的地址空间。2⁵⁶ 的物理内存空间在可预见的未来也足够容纳许多 I/O 设备和内存芯片。如果需要更多空间，RISC-V 设计者还定义了 **Sv48** 模式，支持 48 位虚拟地址 \[3]。
