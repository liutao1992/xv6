## Project Overview

xv6-riscv is a teaching operating system - a re-implementation of Unix Version 6 for modern RISC-V multiprocessors. It's designed for MIT's 6.1810 course and written in ANSI C.

## Essential Commands

### Build and Run
```bash
make clean          # Clean build artifacts
make               # Build kernel and user programs
make qemu          # Run xv6 in QEMU emulator
make qemu-gdb      # Run with GDB debugging support (run 'gdb' in another terminal)
```

### Testing
```bash
make qemu          # Then in xv6 shell: usertests     # Run all system call tests
make qemu          # Then in xv6 shell: usertests -q  # Run quick tests only
make qemu          # Then in xv6 shell: forktest      # Test process creation
```

### Development Tools
```bash
# Generate assembly listings (already done during build)

# User program assembly: user/*.asm

# Debug with GDB
make qemu-gdb      # Terminal 1

```

## Architecture Overview

### Memory Layout
- **Kernel**: Runs in supervisor mode at high virtual addresses (kernel/memlayout.h)
- **User Processes**: Each has separate address space with text, data, heap, stack
- **Virtual Memory**: RISC-V Sv39 paging with 3-level page tables

### Key Kernel Components

**Process Management** (kernel/proc.c, kernel/proc.h):
- Process table with NPROC entries
- CPU scheduler with round-robin algorithm
- Context switching via swtch.S
- Fork, exec, wait, exit system calls

**Memory Management** (kernel/vm.c, kernel/kalloc.c):
- Physical page allocator using free list
- Kernel page table setup
- User address space management
- Copy-on-write fork optimization

**File System** (kernel/fs.c, kernel/file.c):
- Unix-like file system with inodes
- Logging for crash consistency
- Buffer cache for disk blocks
- Path name resolution

**System Calls** (kernel/syscall.c, kernel/sys*.c):
- System call interface via ecall instruction
- 20+ system calls (open, read, write, fork, etc.)
- Argument validation and copying

**Device Drivers**:
- Virtio disk driver (kernel/virtio_disk.c)
- UART console (kernel/uart.c, kernel/console.c)
- PLIC interrupt controller (kernel/plic.c)

### User Space
- Shell (user/sh.c) with basic job control
- Standard utilities: ls, cat, echo, grep, mkdir, rm, wc
- User library (user/ulib.c) with system call wrappers
- Memory allocator (user/umalloc.c)

## Code Conventions

### Error Handling
- Kernel functions return -1 on error, 0 on success
- User programs use exit(1) for errors, exit(0) for success
- Panic() for unrecoverable kernel errors

### Locking
- Spinlocks for short critical sections (kernel/spinlock.c)
- Sleep locks for longer operations (kernel/sleeplock.c)
- Always acquire locks in consistent order to avoid deadlock

### Naming Conventions
- Kernel files: lowercase with underscores
- User programs: prefixed with underscore (_ls, _cat)
- System calls: prefixed with sys_ (sys_open, sys_fork)
- Global kernel functions: no prefix

## Testing Philosophy
- usertests.c contains comprehensive system call tests
- Each test runs in separate process
- Tests should be idempotent and not depend on previous state
- Quick tests (-q flag) for development iteration

## Common Development Tasks

### Adding a System Call
1. Add syscall number to kernel/syscall.h
2. Implement sys_name() in appropriate sys*.c file
3. Add to syscalls[] array in kernel/syscall.c
4. Add user wrapper to user/user.h and user/usys.pl

### Adding a User Program
1. Create source file in user/
2. Add to UPROGS in Makefile
3. Follow existing patterns for argument parsing and error handling

### Debugging Tips
- Use printf() in kernel code (after consoleinit())
- Use panic() for assertion failures
- Check kernel/kernel.asm for generated assembly
- Use gdb with qemu-gdb for source-level debugging
- Usertrap messages often indicate system call issues
