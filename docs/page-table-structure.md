# 页表结构详解

## 1. 页表基本概念

### 1.1 什么是页表
页表（Page Table）是操作系统内存管理的核心数据结构，用于实现虚拟内存到物理内存的地址转换。它建立了虚拟地址空间与物理地址空间之间的映射关系。

### 1.2 为什么需要页表
1. **内存保护**：不同进程的虚拟地址空间相互隔离
2. **内存共享**：多个进程可以共享同一块物理内存
3. **内存抽象**：为每个进程提供独立的地址空间
4. **内存管理**：支持按需分配、写时复制等高级功能

## 2. 页表类型

### 2.1 单级页表
- **结构**：一个大的线性表，直接映射虚拟页号到物理页号
- **优点**：简单直接，查找速度快
- **缺点**：内存占用巨大（64位系统需要数TB的页表空间）

### 2.2 多级页表
- **结构**：树状层次结构，按需分配页表项
- **优点**：节省内存空间，支持稀疏地址空间
- **缺点**：查找需要多次内存访问

## 3. RISC-V Sv39 页表结构

xv6 使用 RISC-V Sv39 页表结构，这是一个三级页表系统。

### 3.1 虚拟地址格式
```
虚拟地址（39位有效）：
┌─────────────┬─────────────┬─────────────┬─────────────┐
│   VPN[2]    │   VPN[1]    │   VPN[0]    │   Offset    │
│   (9位)     │   (9位)      │   (9位)     │   (12位)    │
└─────────────┴─────────────┴─────────────┴─────────────┘
  38        30 29        21 20        12 11           0
```

- **VPN[2]**：第一级页表索引（9位，512个条目）
- **VPN[1]**：第二级页表索引（9位，512个条目）
- **VPN[0]**：第三级页表索引（9位，512个条目）
- **Offset**：页内偏移（12位，4KB页面）

### 3.2 页表项（PTE）结构
```
页表项（64位）：
┌─────────────────────────────────────────────┬─────────────┐
│              PPN (44位)                     │   标志位     │
│         物理页号                             │   (10位)     │
└─────────────────────────────────────────────┴─────────────┘
 63                                        10 9           0
```

### 3.3 权限位说明
- **V (Valid)**：页表项是否有效
- **R (Read)**：是否可读
- **W (Write)**：是否可写
- **X (Execute)**：是否可执行
- **U (User)**：用户模式是否可访问
- **G (Global)**：全局页面（TLB不会因地址空间切换而失效）
- **A (Accessed)**：是否被访问过
- **D (Dirty)**：是否被修改过

## 4. 地址转换过程

### 4.1 详细转换步骤
以虚拟地址 `0x123456789` 为例：

```
虚拟地址：0x123456789
二进制：  000100100011010001010110011110001001
分解：
- VPN[2] = 000100100 = 36
- VPN[1] = 011010001 = 209  
- VPN[0] = 010110011 = 179
- Offset = 110001001 = 393
```

**转换过程：**
1. **第一级查找**：
   - 从 satp 寄存器获取根页表物理地址
   - 使用 VPN[2] (36) 作为索引
   - 读取 PTE[36]，获取第二级页表地址

2. **第二级查找**：
   - 使用 VPN[1] (209) 作为索引
   - 读取第二级页表的 PTE[209]，获取第三级页表地址

3. **第三级查找**：
   - 使用 VPN[0] (179) 作为索引
   - 读取第三级页表的 PTE[179]，获取物理页号

4. **最终地址**：
   - 物理地址 = 物理页号 << 12 + 页内偏移

### 4.2 代码实现示例
在 xv6 的 `walk()` 函数中体现：

```c
pte_t *
walk(pagetable_t pagetable, uint64 va, int alloc)
{
  // 遍历三级页表
  for(int level = 2; level >= 0; level--) {
    // 提取当前级别的VPN
    pte_t *pte = &pagetable[PX(level, va)];
    
    if(*pte & PTE_V) {
      // 页表项有效，获取下一级页表
      pagetable = (pagetable_t)PTE2PA(*pte);
    } else {
      // 页表项无效，按需分配
      if(!alloc || (pagetable = (pde_t*)kalloc()) == 0)
        return 0;
      memset(pagetable, 0, PGSIZE);
      *pte = PA2PTE(pagetable) | PTE_V;
    }
  }
  return &pagetable[PX(0, va)];
}
```

## 5. TLB 优化机制

### 5.1 TLB 工作原理
- **TLB (Translation Lookaside Buffer)**：地址转换缓存
- **作用**：缓存最近使用的虚拟地址到物理地址的映射
- **效果**：避免每次地址转换都访问内存中的页表

### 5.2 TLB 管理
```c
// 刷新TLB
static inline void
sfence_vma()
{
  // 刷新当前CPU的TLB
  asm volatile("sfence.vma zero, zero");
}
```

## 6. 大页面支持

### 6.1 大页面概念
- **普通页面**：4KB (2^12)
- **大页面**：2MB (2^21) 或 1GB (2^30)
- **优势**：减少TLB缺失，提高性能

### 6.2 大页面实现
在中间级别的页表项中直接存储物理地址，而不是指向下一级页表。

## 7. 页表在操作系统中的应用

### 7.1 进程隔离
```c
// 每个进程有独立的页表
struct proc {
  pagetable_t pagetable;  // 用户页表
  // ...
};
```

### 7.2 内存共享
- **共享库**：多个进程映射到同一物理页面
- **父子进程**：fork() 后共享只读页面

### 7.3 写时复制（COW）
```c
// 标记页面为只读，写入时触发页面错误
*pte = PA2PTE(pa) | PTE_V | PTE_U;  // 去掉 PTE_W
```

### 7.4 懒分配
```c
// vmfault() 处理页面错误
int
vmfault(pagetable_t pagetable, uint64 va)
{
  if(va >= MAXVA)
    return -1;
    
  char *mem = kalloc();
  if(mem == 0)
    return -1;
    
  memset(mem, 0, PGSIZE);
  if(mappages(pagetable, PGROUNDDOWN(va), PGSIZE, 
              (uint64)mem, PTE_W|PTE_R|PTE_U) != 0) {
    kfree(mem);
    return -1;
  }
  return 0;
}
```

## 8. 页表结构的优缺点

### 8.1 优点
1. **内存效率**：按需分配，节省内存
2. **灵活性**：支持稀疏地址空间
3. **安全性**：提供细粒度的权限控制
4. **可扩展性**：支持大地址空间

### 8.2 缺点
1. **性能开销**：多级查找增加内存访问次数
2. **复杂性**：实现和调试相对复杂
3. **内存碎片**：页表本身可能产生内存碎片

## 9. xv6 中的页表实现特点

### 9.1 内核页表设计
- **直接映射**：内核虚拟地址 = 物理地址
- **权限分离**：代码段只读，数据段可读写
- **设备映射**：UART、PLIC等设备的内存映射

### 9.2 用户页表设计
- **独立地址空间**：每个进程有独立的用户页表
- **安全隔离**：用户页面标记为 PTE_U
- **动态分配**：按需分配和释放页面

### 9.3 关键函数
- **walk()**：页表遍历
- **mappages()**：建立映射
- **uvmalloc()**：用户内存分配
- **uvmcopy()**：页表复制
- **copyout()/copyin()**：内核用户数据传输
